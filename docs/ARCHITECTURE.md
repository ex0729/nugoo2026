# 아키텍처

## 기술 방향

- 운영 인증·DB: Supabase Auth + PostgreSQL + RLS
- 운영 배포: Vercel Next.js
- 관리자 인증: Supabase 이메일·비밀번호 로그인, 서버 쿠키 세션
- 권한 변경: 서버 API → 보안 정의자 RPC → 내부 역할 검증 → 감사 로그
- 배포 산출물은 Vercel의 Next.js(`pnpm build`)와 비공개 Sites의 Vinext(`pnpm build:sites`)를 분리한다.

- UI: React 19 + TypeScript + Vinext(App Router 호환)
- 스타일: Tailwind 기반 빌드 위에 프로젝트 전용 CSS 디자인 토큰
- 호스팅: Cloudflare Workers 호환 ESM, Sites 배포
- 데이터: 초기에는 타입이 지정된 목업 저장소, 상용 단계에서는 관계형 DB와 Drizzle ORM
- 인증: 관리자 세션 인증 + 강사 개인별 만료형 응답 토큰
- 알림: `NotificationProvider` 인터페이스 뒤에 카카오 알림톡 공급자 어댑터 연결

## 상용 목표 구조

```text
브라우저
  ├─ 관리자 웹 ── 세션 인증/RBAC ─┐
  └─ 강사 모바일 ─ 보안 응답 토큰 ├─ 도메인 서비스 ─ 관계형 DB
                                  ├─ 알림 아웃박스 ─ 카카오 어댑터
                                  └─ 감사 로그
```

## 경계

- 표현 계층은 도메인 상태를 직접 변경하지 않고 명령형 서비스에 요청한다.
- 배정 확정은 수업 잠금, 인원 검증, 역할 검증, 일정 생성, 이력 기록을 한 트랜잭션으로 처리한다.
- 알림 발송은 DB 트랜잭션과 분리된 아웃박스로 처리해 재시도와 중복 방지를 지원한다.
- 모든 날짜는 저장 시 UTC, 표시와 마감 판정은 Asia/Seoul 기준으로 처리한다.
- 업체 식별자를 모든 업무 엔티티에 포함해 다중 교육업체 확장에 대비한다.

## 배포 환경

- local: 목업/로컬 D1
- preview: 테스트 데이터와 샌드박스 알림 공급자
- production: 운영 DB, 비밀값 관리, 실제 알림 공급자

## 확장 원칙

- 카카오 공급자와 인증 공급자를 인터페이스로 격리한다.
- 출석·수업일지·정산은 Phase 1 배정 도메인과 분리된 모듈로 추가한다.
- 수업료는 현재 안내·스냅샷만 담당하고 계산·지급 로직과 분리한다.
