# 테스트 전략

최종 운영 출시 판정에는 [`FINAL_SERVICE_QA_CHECKLIST.md`](./FINAL_SERVICE_QA_CHECKLIST.md)를 사용한다.

## 단위 테스트

- 시간 구간 충돌 판정
- 역할별 인원 제한
- 조건부 응답 사유 검증
- 역할별 수업료 필수 조건
- 토큰 만료와 요청 종료 판정

## 통합 테스트

- 수업 생성 → 모집 → 역할별 응답 → 최종 배정
- 중복 응답과 중복 알림 방지
- 배정과 확정 일정 생성의 원자성
- 수업료 변경 이력과 배정 당시 스냅샷 유지
- 권한별 데이터 접근 차단

## E2E

- 관리자의 전체 배정 흐름
- 강사의 모바일 응답 및 변경
- 만료 링크, 종료 요청, 일정 변경, 취소
- 데스크톱 1280px 이상과 모바일 360~430px

## 현재 완료 기준

- TypeScript 컴파일 및 프로덕션 빌드 성공
- 핵심 상호작용과 반응형 레이아웃 구현
- 상태를 색상만으로 구분하지 않음
- 빈 상태·오류·마감 상태 설계 반영
