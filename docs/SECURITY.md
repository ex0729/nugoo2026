# 보안 설계

- 최고관리자는 사전 허용된 이메일의 최초 가입 때만 생성하며, 데이터베이스 고유 제약으로 1명만 허용한다.
- 관리자 페이지와 API는 서버에서 세션과 활성 역할을 함께 검증한다.
- 클라이언트에는 Supabase 공개용 publishable key만 제공하며 service role key는 사용하지 않는다.
- 회원 정보는 RLS로 본인 또는 활성 관리자만 조회할 수 있다.
- 서비스 관리자는 최고관리자를 변경하거나 다른 서비스 관리자를 임명할 수 없다.
- 모든 회원 권한·상태 변경은 관리자 감사 로그에 기록한다.
- 운영 로그인 화면에서는 신규 가입을 제공하지 않으며 사전 생성·확인된 최고관리자 계정만 비밀번호 인증을 사용할 수 있다.
- 강사 가입 시 요청 역할은 `instructor`로만 제한하고, 계정 생성 트리거가 모든 신규 일반 계정을 `pending` 상태로 저장한다.
- 관리자 초대 토큰은 256비트 난수로 생성하고 SHA-256 해시만 저장하며 이메일·7일 만료·단일 사용 조건을 모두 검증한다.
- 운영관리자 초대와 기존 관리자 변경은 최고관리자만 수행하며 최고관리자 계정은 일반 변경 함수로 수정할 수 없다.
- 로그인 세션 조회는 현재 로그인한 관리자 본인의 세션만 반환하고, 다른 기기 로그아웃은 Supabase의 `others` 범위를 사용한다.
- 감사 기록은 서버 허용 목록에 정의된 중요 작업만 기록하며 일반 사용자가 임의 작업명을 삽입할 수 없다.

- 관리자는 짧은 수명의 세션과 역할 기반 접근 제어를 사용한다.
- 강사 응답 링크는 128비트 이상의 난수 토큰 원문을 저장하지 않고 해시만 보관한다.
- 토큰은 수신자·요청·만료 시각·요청 버전에 귀속한다.
- 만료·종료·취소·교체된 요청은 제출할 수 없다.
- 응답 API는 idempotency key와 DB 고유 제약으로 중복 제출을 안전하게 처리한다.
- 최종 배정은 트랜잭션과 낙관적 버전 검사를 사용한다.
- 알림 발송은 idempotency key를 가진 아웃박스로 중복을 방지한다.
- 연락처와 기관 담당자 정보는 최소 권한 사용자에게만 노출한다.
- 관리자 변경, 수업료 변경, 배정 변경은 actor·시각·전후 값을 감사 로그로 남긴다.
- 운영 비밀값은 저장소나 클라이언트 번들에 포함하지 않는다.
- 비밀번호 복구는 Supabase PKCE 코드 교환을 사용하며 기존 비밀번호·임시 비밀번호·service role 키를 사용하지 않는다.
- 복구 요청 결과는 가입 여부와 무관하게 동일하게 표시하고 이메일·비밀번호·토큰을 URL 또는 애플리케이션 로그에 남기지 않는다.
- 콜백 이동 경로는 고정 허용 목록만 사용하며, 코드 교환으로 생성된 사용자 세션과 10분 유효 HttpOnly 복구 표식이 모두 있을 때만 새 비밀번호 화면을 활성화한다.
- 비밀번호 변경 후 복구 표식을 폐기하고 Supabase 전체 세션 로그아웃을 수행한다.
